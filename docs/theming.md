# Theming and Palette

`Maizzlex` ships a small host-side palette helper for Maizzle.

Instead of forcing you to hand-maintain full Tailwind color scales, the host app declares semantic base colors and `Maizzlex` expands them into `50..950` shades.

## Where theming lives

The host app owns:

- `maizzle/config.js`
- `maizzle/tailwind.config.js`
- `maizzle/css/tailwind.css`
- `maizzle/utils/palette.js`

The palette is resolved directly inside `tailwind.config.js`, so there is no generated CSS file to keep in sync.

## Base color configuration

After `mix igniter.install maizzlex`, the host app gets this section in `maizzle/config.js`:

```js
maizzlex: {
  gettextModule: "MyAppWeb.Gettext",
  baseColors: {
    primary: "#A75035",
    secondary: "#B47614",
    accent: "#823558",
    info: "#2196F3",
    success: "#4CAF50",
    warning: "#ED6C02",
    error: "#D32F2F",
    content: "#4A443C",
  },
},
```

Supported semantic keys:

- `primary`
- `secondary`
- `accent`
- `info`
- `success`
- `warning`
- `error`
- `content`

You can override any subset of them:

```js
maizzlex: {
  gettextModule: "MyAppWeb.Gettext",
  baseColors: {
    primary: "#0057B8",
    secondary: "#00A86B",
    content: "#2A2A2A",
  },
},
```

Any missing keys fall back to the defaults from `palette.js`.

## Generated shades

Each base color becomes a full scale:

- `50`
- `100`
- `200`
- `300`
- `400`
- `500`
- `600`
- `700`
- `800`
- `900`
- `950`

The `500` shade is always the exact base color. Lighter shades are mixed toward white, darker shades toward black.

## Using theme colors in templates

Once resolved by `tailwind.config.js`, the colors are available as standard theme tokens in Maizzle/Tailwind:

```html
<div class="bg-primary-50 text-content-900 border border-primary-200">
  <h1 class="text-primary-700">Welcome</h1>
  <p class="text-content-700">Thanks for joining.</p>
</div>
```

Typical usage patterns:

- `bg-primary-*` for blocks and surfaces
- `text-content-*` for readable text hierarchy
- `bg-success-*`, `bg-warning-*`, `bg-error-*` for status messaging
- `accent-*` for secondary emphasis

## How theme resolution works

The scaffolded `tailwind.config.js` imports the host config and expands the palette directly:

```js
import emailPreset from "tailwindcss-preset-email"

import maizzleConfig from "./config.js"
import { buildPalette } from "./utils/palette.js"

const baseColors = maizzleConfig.maizzlex?.baseColors || {}

export default {
  content: [
    "./components/**/*.html",
    "./emails/**/*.html",
    "./layouts/**/*.html",
  ],
  presets: [emailPreset],
  theme: {
    extend: {
      colors: buildPalette(baseColors),
    },
  },
}
```

`tailwind.css` points Maizzle at that Tailwind config:

```css
@config "tailwind.config.js";
@tailwind components;
@tailwind utilities;
```

## Gettext in layouts

The scaffolded `config.js` also stores the host Gettext module:

```js
maizzlex: {
  gettextModule: "MyAppWeb.Gettext",
  ...
}
```

That value is used only by the scaffolded layout/template files generated by Igniter. It exists so the host app can change the imported Gettext module when installing or generating templates.
